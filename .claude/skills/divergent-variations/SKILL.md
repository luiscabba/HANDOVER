# Divergent variations

Options fail when they share one skeleton and only swap colour and font. A viewer squints, sees the same picture six times, and cannot choose. This skill forces real difference before anything is drawn.

No em dashes in any output.

## 1. Plan the set before drawing

Write a variation matrix first (in the reply or working notes, never on the canvas). One row per option, one column per axis below. Fill every cell before building.

| Axis | What changes | Examples |
| --- | --- | --- |
| Layout archetype | The skeleton of the page or board | Product window hero, full-bleed poster, bento grid, editorial columns, single object as the page, map or diagram as hero, floating layered panels, scrolling story |
| Material and surface | What things are made of | Flat print, frosted glass, paper label, dark console, soft 3D, photographic, sticker and cut-out, hard-edged brutalist |
| Type genre | The kind of typography, not just a family | Tight grotesk, condensed poster, editorial serif, rounded geometric, monospace data, wide display |
| Imagery mode | What carries the visual | Product UI, photography, illustration from shapes, data and maps, the trade's own artifacts (labels, forms, receipts), pure type |
| Colour strategy | How colour is used, not which hue | Monochrome plus one signal, dark mode, multi-colour play, tinted light, colour as data, gradient light |
| Density and rhythm | How full the space is | Sparse and calm, dense and technical, loud and oversized, modular |
| Mark construction | How the logo is built | Wordmark only, letterform built from shapes, abstract symbol, badge or seal, mark taken from the trade's vernacular |
| Voice | How the copy sounds | Plain expert, warm guide, quiet authority, loud and blunt, playful |

## 2. Difference rules

- Every pair of options differs on **at least 4 axes**, and two of them must be **layout archetype** and **material**. Colour alone never counts as a difference.
- No two options share a layout archetype or a mark construction.
- Each option is named after its style, not its colour: "Console SaaS", "Liquid Glass", "Dispensing Label", not "Green" or "Blue".
- Each option draws from a different school of reference. Name one or two real, shipped references per option (Linear, Apple Liquid Glass, Swiss posters, pharmacy labels, Mailchimp illustration) so the style is anchored, then do not copy them.
- Include **one wild card** per set: the option that feels slightly too far. It shows where the edge is.
- When the user asks for specific styles (for example SaaS, liquid glass), each one gets its own option and is pushed to the clearest version of that style.

## 3. Keep the comparison fair

- Same artboard size and the same set of proof surfaces in every option, so options are compared on style, not content. Typical surfaces: logo at full size and at 16 px, website hero, one product or app screen, one social post, the brand placed in someone else's context.
- The surfaces may be arranged differently per option. A shared checklist is required; a shared layout is forbidden.
- Real or bracketed copy only, never lorem ipsum. Contrast ratios computed in code for every text and background pair.

## 4. Squint test before presenting

Before sending, check the set as thumbnails:

1. Could someone tell every option apart in greyscale at thumbnail size? If two look alike, rebuild one with a different layout archetype and material.
2. Does each option have one thing only it does (a map as hero, a label as layout, glass layers, a giant capsule)? If not, it is not a direction yet.
3. Would a designer call these different styles, or the same style in different colours? Only the first passes.

## 5. Per output type

- **Branding:** vary mark construction, type genre and imagery mode first. Show each mark at 16 px.
- **Websites:** vary layout archetype and section rhythm first. Each hero states its idea differently: product, object, data, people, type.
- **Marketing posts:** vary format (statement, carousel cover, data card, sticker, photo with overlay) and the hook, not only the palette.
- **Applications and UI:** vary information density, component material (flat, glass, card, table-first) and navigation model, while keeping the same task flow so options stay comparable.

## 6. Iteration

- Never edit an option in place. New variations get new names; retired options move to an Explorations area with a dated one-line reason.
- A user pick narrows the next round: hold the picked option's layout archetype and material, then vary the remaining axes.
