# How we work

These are the rules both projects were built under. The clients have seen work made this way; keep it consistent.

## Method, in order

1. **Purpose first.** Before a new screen or section, write down who it is for and the one job it does (skill: `screen-purpose-pass`).
2. **Reference study.** Pull 6 to 8 real references (how comparable products handle it), capture them live, compare, and say what it changes for us (skill: `reference-study`). Every past study is linked in each project's `DESIGN.md`.
3. **Mockups, not descriptions.** Every visual decision is shown in real use. Never a list of names or a written description of a look.
4. **Divergent options.** When offering directions, each one is a genuinely different style (layout, material, type, imagery), not the same layout recoloured (skill: `divergent-variations`).
5. **Pick, then build.** Only build what was picked. Record the pick in `DECISIONS.md` with the date.
6. **Prototype risky motion first.** Scroll effects and 3D get a lab page before they go on the live site.

## House rules

- **Headers say what is on them.** "For buyers", "How the review works", "Usage guidelines". No slogans or clever lines on pages, boards or token names (skill: `no-ai-slop-systems`).
- **Less text, more visual.** Cut copy until each section reads at a glance. Sections must not look flat or static next to animated ones.
- **No em dashes** in any copy.
- **Each page section is custom-fit** to what its information is trying to show. Do not reuse the same section design across pages.
- **Placeholders are visible.** Facts the client has not supplied go in as `[bracketed]` text, never invented.
- **Working answers are tagged.** Where we assumed something on the client's behalf, mark it as a working answer for them to confirm.
- **Mobile is not an afterthought.** Animations keep moving on phones; key 3D moments stay 3D.
- **Public material never reveals method.** No naming competitors; no describing texxen's own techniques. State the obvious only.
- **Client copy uses the texxen voice** (skill: `texxen-voice`).

## Client-facing documents

Show the thinking first, then the output. Keep it visual and light. Decks: narrative first (stage and credibility, quick context, the problem, why the solution is obvious once you see it, how it turned out, results), one idea per slide in big type.
